# parley-emit — test plan

Evidence lives in `packages/parley-emit/test/`. Where a case says the run conforms, it runs the
doctor (`scripts/doctor.ts`) over the captured streams and asserts zero violations against the
repository's schemas; cases about a single field or a refusal assert that field.

| ID | Requirement | Spec |
| --- | --- | --- |
| PE-1 | A tool conforms by constructing a writer and emitting through it; every line validates against the schema for its exact pair | §1, §4.4, §4.5 |
| PE-2 | `inv` is computed over input bytes; stable across reruns, changed by editing an input; omitted when it cannot be made safe | §2.2 |
| PE-3 | The bootstrap line is emitted before work begins and names a receipt that already exists | §3.1 |
| PE-4 | An uncaught throw produces a conforming error line and a readable, complete failed receipt; exit 2 | §6, §3.3 |
| PE-5 | Retention is stated, enforced by count, configurable, recorded, and skipped on a dry run | §5.1, §4.3 |
| PE-6 | Repository hygiene: `.parley/.gitignore` with `*` on first write, never overwritten; a user's file sends the run to the fallback with a warning | §5.2 |
| PE-7 | Declared secrets never reach any stream; the head records every redaction; later surfacings are replaced and recorded by `redaction` events; `end.redacted` aggregates | §5.3, §3.3 |
| PE-8 | Startup failure is one stderr line and exit 3; the fallback location is used before failing | §3.2, §5 |
| PE-9 | Sink failure before `end` is an error line on a working sink and exit 4; nothing follows `end` | §5.4, §3.3 |
| PE-10 | Discovery is a run: `--schema` and `<command> --help` bootstrap, write a receipt, and close with `end` | §4.1, §4.2 |
| PE-11 | A record over 65,536 bytes is stored as a sidecar whose event describes the stored bytes | §5 |
| PE-12 | No run emits a non-JSON line on any stream, whatever a record contains; a library's console output is captured into the receipt | §1.1, §1.2 |
| PE-13 | The shipped schemas are byte-identical to the repository's top-level schemas and pinned by commit | §4.5 |
| PE-14 | A declared secret value reaches no stream, receipt or `inv` on any path: no command selected, discovery, a secret inside the working-directory path, a secret colliding with an envelope word, a secret in an input path | §5.3, §2.2, §3.2 |
| PE-15 | A throw from a tool callback before the bootstrap line is a startup failure; a throwing renderer falls back | §3.2, §6 |
| PE-16 | Retention never deletes a receipt still in flight (no `end`, modified within 24 hours) and deletes a bundle's sidecars with it | §5.1 |

| PE-20 | Smaller gaps: prototype names are not commands; `end(0)` after an error is refused; state-directory retention is declared; an empty secret is recorded; the ignore file is created whole | §4.3, §3.4, §5.2, §5.3 |
| PE-21 | From the blind pass and the checker: a stalled pipe reader does not fail stdout; a secret as a number, boolean or key is redacted and out of `inv`, while the writer's own scalars are untouched; nested secrets leave no tail; a secret in the session is a startup failure; a failed sidecar keeps the record inline; a startup problem never carries a secret | §5.4, §5.3, §2.2, §5, §3.2 |
| PE-22 | The shared history stream: opt-in by `PARLEY_HISTORY` or the known state directory; the receipt's bytes and nothing else; one timeline across tools, repositories and agents; whole-line appends under concurrency; retention by daily segment; a path or field name the bootstrap line could not print without disclosing a declared secret means no stream; no effect whatever on a run with no stream configured | §8 (informative), §5, §5.1, §5.3 |
| PE-23 | The history sink's user-defined transform: configured in code, enforced around; the envelope reattached after it, the returned body re-validated against its exact pair, a withheld line warned by `seq` without changing the exit status, the projection named on the stream copy alone, and no effect at all on a run without one | §8 (informative), §1.3, §4.5, §5.3, §6.1 |
| PE-24 | The built-in `declaredProjection(values)`: the same §5.3 scrubber the receipt uses, applied to the body with a second declared set; longest-first, key renaming, the envelope untouched; an empty set is the identity and configures no transform at all; the transform's name and digest never disclose what it declared | §8 (informative), §5.3, §1.3 |
| PE-25 | The built-in `refuseSuspectedSecrets`: a line whose body matches one of a documented list of token shapes is withheld from the stream, kept in the receipt, and named by `seq` in a `history.suspected_secret` warning; it refuses and never rewrites, never reads the envelope, and never echoes a suspected value — not the matched text and not a pointer built from a token-shaped key | §8 (informative), §5.3, §6.1 |
| PE-26 | Retention is per tool: a tool counts and expires only completed bundles whose head names it; another tool's receipts, a reader's included, are never counted and never deleted; a file whose head cannot be read is not this tool's and is left alone | §5.1 |
| PE-27 | The command is chosen by position (flyingrobots/parley#101): once the writer's own flags are set aside, the first remaining argument is the command, and only that one argument is removed; every other argument, a later one with the command's text included, reaches `resolved`, `inputs` and the handler in order. A first argument that names no command is `startup.unknown_command`, even when a later one names a command; a tool with one command may omit it, and then nothing is removed | — (the spec does not say how a command is selected) |
| PE-28 | `--` ends the writer's flags (flyingrobots/parley#103): the writer's own flags are recognised anywhere before the first `--`; that `--` is removed, and every argument after it reaches `resolved`, `inputs` and the handler untouched, one with a writer flag's text or a second `--` included. The command is the first argument before the `--`; nothing after it is ever taken as the command | — (the spec does not say how a writer's flags are recognised) |
| PE-29 | A record that redaction made invalid under its declared schema is never published (flyingrobots/parley#131): a tool's record in which the scrub replaced something is validated, as each sink would receive it, before any copy is written and before a `seq` is taken; on failure nothing of it is written, one `redaction.schema_conflict` error names each field by JSON Pointer and the schema pair and carries no value, validator message or schema fragment, the call throws `ParleyRedactionConflict`, and the run ends with status 4 whatever the handler asks for. A record redaction left valid, one that was already invalid, and one whose type has no schema document are written as before | §5.3, §3.4, §6 |
| PE-30 | A record redaction changed, whose pair has a schema document the writer holds and cannot evaluate, is withheld like a conflict (flyingrobots/parley#144): nothing of it is written, no `seq` is taken, one `redaction.schema_unchecked` error names the schema pair and the pointers the scrub replaced and carries no value, validator message or part of the schema (the unevaluable construct's name included), the call throws `ParleyRedactionUnchecked`, and the run ends with status 4. A record the scrub did not change, and a record of a type with no schema document, are written as before | §5.3, §3.4, §6 |
| PE-35 | A `bigint` in a payload is carried exactly through the whole output path (flyingrobots/parley#171): written as a JSON number of exact unquoted digits on stdout, in the receipt, in a sidecar and on the shared stream; reparsed exactly before a history transform; redacted when it equals a declared secret and left exact beside another redacted field; decided exactly by the post-redaction check or reported as unchecked, never checked as a rounded number; exact in `inv` and the canonical form, with every identity of a value supported before unchanged; never a throw in `--human`, an error path or the top-level handler. The exact parser and serialiser are the writer's and exported. The writer refuses a `bigint` where it needs a safe integer and one it could not read back | §1.1, §2.2, §5.3, §8 (informative) |
| PE-36 | What is scrubbed is what is written (flyingrobots/parley#178): with a secret present, a value with a `toJSON` hook, own or inherited, is scrubbed as what the hook returns, once, and a boxed primitive as its primitive, so a secret only a hook returns is replaced and a `Date` is not rewritten as `{}` | §5.3 |
